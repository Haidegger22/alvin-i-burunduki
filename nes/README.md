# NES-версия (RetroArch)

Здесь лежит настоящий образ картриджа для NES: игра написана на C под cc65,
собрана в ROM (NROM-256, mapper 0) и запускается в RetroArch ядром nestopia.

**Почему отдельная версия.** Браузерную игру нельзя «упаковать» в NES-образ —
другая платформа: 256×240 точек, 4 цвета на спрайт, 2 КБ оперативной памяти,
процессор 6502. Игра перенесена заново: механика и уровни те же, графика
перегнана в формат NES (плитки 8×8, два битовых слоя, палитры).

---

## 1. Что нужно

| Что | Зачем | Проверка |
|---|---|---|
| `cc65` (пакет Debian: `cc65`) | компилятор для 6502: `cl65`, `ca65`, `ld65` | `cl65 --version` |
| `python3-pil` | сборка графического ПЗУ из PNG | `python3 -c "import PIL"` |
| RetroArch + ядро nestopia | запуск ROM | `ls /usr/lib/*/libretro/nestopia_libretro.so` |

```bash
sudo apt install -y cc65 python3-pil retroarch libretro-nestopia
```

---

## 2. Сборка

```bash
cd nes
make            # обычная сборка  -> build/alvin.nes
make demo       # сборка с авто-пилотом -> build/alvin-demo.nes (для проверки и записи видео)
make chr        # пересобрать графическое ПЗУ из assets/sprites/
make clean      # убрать сборку
```

Устройство проекта:

```
cfg/nrom.cfg        конфигурация линковки (карта памяти NROM без ОЗУ картриджа)
src/crt0.s          старт: заголовок картриджа, инициализация PPU, NMI, векторы
src/chrdata.s       подключение 8 КБ графического ПЗУ в сегмент CHARS
src/game.c          вся игра: ввод, физика, уровень, игрок, индикатор кнопок
src/hw.h            адреса регистров PPU/APU/геймпада
tools/make_chr.py   PNG -> плитки NES (два битовых слоя) + палитры
tools/nes_input_test.py  автопроверка кнопок (запускает RetroArch и жмёт клавиши)
```

## 3. Запуск

```bash
retroarch -L /usr/lib/aarch64-linux-gnu/libretro/nestopia_libretro.so build/alvin.nes
# или положить ROM в свою папку и запускать из интерфейса RetroArch
```

Готовый образ лежит и в `~/roms/nes/Alvin i Burunduki (NES).nes`.

## 4. Управление

| Кнопка NES | Что делает | Клавиша по умолчанию в RetroArch |
|---|---|---|
| Крестовина ← → | идти | стрелки |
| A | прыжок | Z |
| B | взять/бросить ящик (в разработке) | X |
| Start | — | Enter |

Раскладка задаётся в `~/.config/retroarch/retroarch.cfg`
(`input_player1_a`, `input_player1_b`, `input_player1_left` и так далее).

**Проверка кнопок прямо в игре:** над землёй есть ряд из восьми квадратиков —
по одному на каждую кнопку геймпада. Нажал кнопку — квадратик загорелся. Если
при нажатии ничего не горит, значит ввод не доходит до эмулятора (проверьте
раскладку в настройках RetroArch).

## 5. Что уже работает и что дальше

Сделано (этап 1):
- картридж запускается в RetroArch, рисуется экран уровня: небо, земля, платформы, ящики, сердца
- бурундук бегает и прыгает (прыжок выше, если держать кнопку)
- падение в яму отнимает сердце и возвращает на безопасное место
- чтение геймпада и индикатор нажатых кнопок

Дальше по этапам:
1. ящики: поднять, бросить во врага, спрятаться внутри (главная механика оригинала)
2. враги: механический бульдог, робо-крыса, пчела; бонусы и счёт
3. музыка и звуки через APU (чиптюн из браузерной версии, переписанный на 6502)
4. прокрутка уровня и полная длина, финишная дверь

## 6. Грабли, на которые я наступил (чтобы не повторять)

- **Указатель программного стека cc65 живёт по адресу `$0005`, а не `$0000`** — если
  инициализировать не тот адрес, любой код на C падает на первом обращении, а экран
  остаётся пустым. Смотрите карту линковки: `grep '^sp ' build/alvin.map`.
- **Регистры нужно объявлять `volatile`**, иначе компилятор кэширует чтение, и геймпад
  «не работает» (ввод читается один раз и навсегда).
- **Адрес `$3F10` зеркалит `$3F00`** — первая запись палитры спрайтов затирает цвет
  фона. Записывайте цвет фона последним.
- **Таблицу атрибутов (`$23C0`) обязательно заполнять**: если её не тронуть, PPU берёт
  оттуда мусор и цвета уезжают.
- **Порядок загрузки:** плитки → карта уровня → палитра → включить рендеринг.
- **Путь `.incbin` и `-I`**: `chrdata.s` подключает `chr/tiles.chr`, поэтому сборка идёт
  из каталога `nes/`.
- **Заголовки не попадали в зависимости Makefile** — правка `hw.h` не вызывала пересборку;
  теперь `HEADERS` перечислены явно.
